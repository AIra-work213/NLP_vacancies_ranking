# Локальный выпуск и восстановление

Выпуск состоит из кода и uv.lock, configs/search.yaml, архива BM25,
Parquet эмбеддингов и соответствующих документов/векторов PostgreSQL
Модель и revision заданы в конфиге; артефакты содержат версию корпуса
API вычисляет release_version из индексов и эффективного конфига
Этот идентификатор возвращается клиенту и участвует в ключе Redis
Отдельный реестр выпусков не добавлен

## Подготовка кандидата

1. Сохранить прежние файлы и образы до изменения рабочего каталога
2. Подготовить кандидата в отдельном каталоге, сохраняя относительные пути
   configs/search.yaml, data/processed и artifacts/indexes
3. Выполнить локальные проверки, сборку пакета и оценку на validation
   Для сравнения настроить baseline_metrics_path и max_ndcg_regression
   в конфиге оценки; baseline должен использовать те же данные и запросы
4. Проверить API кандидата на другом порту через Uvicorn и HTTPX
   При изменении корпуса использовать отдельную базу PostgreSQL
   При изменении только retrieval-параметров можно читать прежнюю базу
5. Проверить readiness, выдачу, документ по ID, повтор запроса и release_version
   Измерить нагрузку на той машине, где будет выполняться поиск

Нагрузочные замеры не задают универсальный SLA, а маленький бенчмарк
не заменяет независимую разметку реальных запросов

## Сохранение предыдущего состояния

```bash
mkdir -p artifacts/releases
tar -czf artifacts/releases/previous.tar.gz \
  src configs migrations pyproject.toml uv.lock dvc.yaml dvc.lock \
  artifacts/indexes data/processed
docker image tag nlp-ranker-api:local nlp-ranker-api:previous
docker image tag nlp-ranker-demo:local nlp-ranker-demo:previous
```

Не включайте .env в архив исходников
Для нового корпуса также нужна резервная копия PostgreSQL:

```bash
docker compose exec -T postgres pg_dump -U nlp_ranker -d nlp_ranker -Fc \
  > artifacts/releases/previous.dump
```

Команда показана для локальных значений по умолчанию
При других учётных данных используйте значения своей .env

## Переключение

Поддерживается простой выпуск с остановкой сервера
Горячее обновление и несколько workers не реализованы

1. Остановить api и demo: `docker compose --profile demo stop api demo`
   Принятые задачи завершаются перед закрытием ресурсов
2. Заменить конфиг и артефакты согласованным кандидатом
   При изменении корпуса импортировать документы и векторы после миграций
3. Собрать и запустить сервисы командой `make up-all`
4. Проверить /health/ready, поиск и чтение документа по ID
   Убедиться, что release_version соответствует кандидату

Работающий процесс не перечитывает модели и файлы на каждом запросе
Не заменяйте корпус в обслуживающей базе до остановки API

## Откат

1. Остановить api и demo
2. Восстановить previous.tar.gz в корень проекта
3. Если менялся корпус, восстановить совместимую базу из previous.dump
   Восстановление базы перезаписывает её содержимое и выполняется только
   при осознанном откате рабочего корпуса
4. Вернуть сохранённые образы:

```bash
docker image tag nlp-ranker-api:previous nlp-ranker-api:local
docker image tag nlp-ranker-demo:previous nlp-ranker-demo:local
docker compose --profile storage --profile demo up -d --no-build --force-recreate api demo
```

5. Проверить readiness, прежнюю release_version и прежнюю выдачу
   Redis очищать не нужно: ключи разных выпусков разделены
   Старые записи истекают по TTL, текст всё равно читается из PostgreSQL

## Проверка воспроизводимости

DVC хранит файлы в MinIO, а не живую PostgreSQL
В пустой копии проекта с доступным remote выполните `make data-pull`
Затем `make migrate`, `make load-documents`, `make load-dense` и `make up-all`
Для построения файлов заново используется `make data-repro`
MLflow хранит параметры, метрики и исходники экспериментов,
MinIO хранит опубликованные артефакты и manifests
Адреса старых запусков приведены в docs/experiments.md

- DVC восстановил 7 файлов из MinIO в пустой каталог с отдельным кешем
- Восстановленный выпуск загружен кодом из собранного wheel
- BM25 пересобран из восстановленного корпуса, архив совпал побайтово
- Отдельный HTTP-сервер выполнил поиск и чтение документа
- Кандидат с другим candidate_limit получил другую release_version
- Возврат прежнего конфига восстановил версию и порядок выдачи
- Повтор запроса вернул ту же выдачу; Redis разделил выпуски
- Docker заново установил serving/demo зависимости по uv.lock и запустил сервисы

Проверка не меняла рабочие конфиги и документы PostgreSQL
