обучение не выполнялось. BM25: Lucene, k1=1.5, b=0.75, title_repeat=3;
lowercase, без стоп-слов и стемминга, сохранение C++, C# и .NET.
Параметры не подбирались по тесту

NDCG использует линейный gain, MRR threshold 1. Recall не является полнотой

BM25 принят как первый базовый вариант, без автоматического допуска к production

По запросам QA и повара BM25 заметно слабее Java/frontend. QA: NDCG 0.583174,
повар: 0.418992. Для дальнейшего сравнения нужны новые кандидаты dense-поиска
и расширение разметки; сами оценки не меняем ради улучшения цифр

## Поиск по смыслу, блоки 13-15

Используется intfloat/multilingual-e5-small, revision
614241f622f53c4eeff9890bdc4f31cfecc418b3, MIT, CPU, 384 измерения.
Входы начинаются с query: и passage:, векторы нормируются, расстояние cosine.
Предел входа 512 токенов. Из 2058 вакансий 193 длиннее этого предела;
медиана 259, p95 601, максимум 2079 токенов вместе с названием и префиксом

Текст делится токенизатором модели на фрагменты по 384 токена с перекрытием 64.
Название повторяется в каждом фрагменте, не более 48 токенов. Полный текст
сохраняется в PostgreSQL. Получено 2519 фрагментов. Без LangChain.
Поиск использует точное расстояние pgvector, максимум оценки фрагментов
на документ, затем top-k документов. HNSW/IVFFlat для такого корпуса пока не нужны.
Город, формат и опыт отбираются до top-k, неизвестные значения не угадываются

Parquet содержит векторы, фрагменты и конфиг модели. Пакеты по 8 фрагментов,
4 CPU-потока. Завершённые пакеты записываются атомарно в .partial.parquet,
продолжение проверяет корпус, параметры и порядок фрагментов. Один процесс
может строить конкретный файл; другой получает явный отказ на файловой блокировке.
Готовый артефакт с тем же корпусом и конфигом используется повторно.
При изменении алгоритма предобработки нужно пересобрать артефакт,
а не использовать старый файл только с совпадающими настройками

Импорт в PostgreSQL выполняется одной транзакцией, сверяет содержимое документов
под разделяемой блокировкой и допускает повторный импорт без дублей.
Поиск читает согласованный снимок БД, проверяет полноту выпуска и актуальность
документов. Изменение или удаление документа требует пересборки векторов;
оно приводит к явному отказу поиска, а не молчаливому пропуску вакансии.
Другие выпуски векторов могут оставаться в таблице, автоматической очистки пока нет

Сравнивались RRF с k=20/60 и min-max взвешенная сумма с весом dense 0.25/0.5/0.75,
по 50/100 кандидатов каждого метода, только на validation. Нормирование выполняется
отдельно внутри каждой выдачи; одинаковые оценки получают нормированную оценку 1.
Пустые источники допустимы, повторы ID удаляются, равенства разрешаются по ID.
Отказ PostgreSQL или модели не переключает поиск на BM25 незаметно.
Выбран RRF k=60, по 50 кандидатов. Он оставлен основным кандидатом для API

Готовый reranker cross-encoder/mmarco-mMiniLMv2-L12-H384-v1, revision
1427fd652930e4ba29e8149678df786c240d8825, Apache-2.0, CPU.
Он получает запрос и каждый фрагмент вакансии, сохраняет заголовок,
ограничивает запрос 96 токенами, а пару 512 токенами. По документу выбирается
максимальный raw logit, равные оценки сохраняют retrieval-порядок. Оценка не вероятность.
Инференс без градиентов, один слот на объект модели, блокирующие операции вне
цикла событий. Повторная отмена удерживает слот до реального окончания вычисления.
Дообучение не выполнялось. Ранжирование выключено по умолчанию из-за измеренного
снижения качества относительно выбранного RRF и стоимости на CPU

Изолированный пилот с 16 парами показал медиану 2.88 с при batch=8 и 3.71 с
при batch=16, по 3 повтора после прогрева, threads=4. Пик памяти процесса
в этом пилоте около 1.48 GiB. Пилот Encoder с 16 текстами занял 2.90 с,
пик памяти процесса около 1.09 GiB. Это память процесса с библиотеками,
а не только весов модели. Замеры не являются SLA HTTP-сервиса

Модели загружаются из Hugging Face по фиксированным revision, без trust_remote_code.
Веса остаются в локальном кеше Hugging Face. В MinIO/DVC хранится рассчитанный
артефакт эмбеддингов, в MLflow конфиги, версии, метрики и ссылка на его manifest.
Для полностью автономного развёртывания перенос весов предусмотрен будущим выпуском,
текущее восстановление использует кеш или загрузку указанного revision

Карточки моделей:

[mmarco-mMiniLMv2-L12-H384-v1](https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1)

## Другие энкодеры на CPU, 7 октября 2026 года

Сравнение готовых моделей без обучения: E5-small, ruBERT-tiny2 и
paraphrase-multilingual-MiniLM-L12-v2. Только четыре validation-запроса,
test не использовался для выбора. Корпус тот же: 2058 вакансий.
BM25 и RRF k=60, по 50 кандидатов, не перенастраивались под каждую модель

Разметка расширена в отдельном пуле эксперимента: к исходным 254 парам
добавлено 49 проверенных Codex пар из объединения реальных top-10,
включая одну новую положительную оценку. Все семь вариантов пересчитаны
по одной общей разметке, top-10 полностью размечены. Неразмеченные результаты
не отфильтровывались из выдачи. Основной data/qrels.csv не изменялся.
Дополнение: artifacts/reports/encoder-comparison/additional-qrels.csv,
снимок полной validation-разметки сохранён в MLflow как common-qrels.json.
Всего 146 validation-оценок.
Независимой проверки человеком не было. Из-за расширения идеальной выдачи
новые NDCG нельзя напрямую сравнивать с прежним разделом на 254 парах

BM25 на общем пуле: NDCG@10 0.682457.
MiniLM лучше в самостоятельном dense-поиске, но преимущество гибрида над E5
только +0.004564, парный bootstrap 95% интервал
[-0.046018; 0.048825], 10000 повторов, seed=42.
Четыре запроса и подбор по validation не подтверждают устойчивого преимущества.
Поэтому E5 пока остаётся в основном конфиге. ruBERT не выбран:
он часто возвращает вакансии других специальностей по общим формулировкам

Поиск выполнялся точным cosine в NumPy с максимумом оценки по фрагментам,
для всех моделей одинаково. У E5 проверено совпадение всех validation top-10
dense и hybrid с прежним pgvector. Размерности не обрезались и не дополнялись:
E5 и MiniLM 384, ruBERT 312. PostgreSQL и его миграции не изменялись.
Это исследовательское сравнение, новые модели ещё не подключены к pgvector/API.
Префиксы query:/passage: используются только у E5. Pooling берётся из
зафиксированного SentenceTransformer: у ruBERT CLS, у E5/MiniLM mean

MiniLM использует штатное окно 128 токенов, фрагменты 64 с перекрытием 16,
у ruBERT окно ограничено 512, фрагменты 384 с перекрытием 64.
Это сравнение моделей с подходящими им окнами, а не изоляция одной архитектуры.
E5 использует готовые 2519 фрагментов прежнего выпуска.
CPU: threads=4, batch=8, один поток BLAS, без конкурентной нагрузки.
Задержки включают эмбеддинг запроса и поиск в памяти, 10 повторов на запрос
после прогрева. SQL, BM25/RRF, HTTP и Redis не включены.
Время ruBERT для подготовки корпуса около 21 с, MiniLM около 240 с,
без загрузки весов. E5-векторы переиспользованы: его build_seconds
означает чтение готового Parquet и не сравнивается со временем индексации

### Названия дальнейших запусков

CLI теперь создаёт группы вида `multilingual-e5-small - оценка поиска`,
а запуски `multilingual-e5-small - оценка поиска - hybrid, validation`.
Этап подготовки эмбеддингов называется отдельно. Для своего названия
доступны --experiment и --run-name. Пользовательское значение
NLP_RANKER_MLFLOW_EXPERIMENT сохраняется, если оно отличается от прежнего
значения по умолчанию nlp-ranker. Старые эксперименты и запуски не переименованы.
Связи с индексами ищутся между группами по версии артефакта
