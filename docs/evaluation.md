# Критерии готовности и протокол оценки

## Стартовый бенчмарк

Инструкция версии 2. Разметку выполнил Codex: 12 разных намерений, 254 оценки после блоков 13-15.
В каждом разбиении по 4 запроса: train - данные, бухгалтерия, 1С, продажи;
validation - QA, повара, Java, frontend; test - доставка, junior PHP,
процедурная медсестра, уборка. Перефразировки не увеличивают размер набора

Единая шкала:

- **2** - роль/задачи и все запрошенные условия подтверждены
- **1** - подходящая роль или существенная часть задач; некоторые условия
  неизвестны либо неоднозначны, без явного противоречия
- **0** - другая роль/задачи либо явное противоречие обязательному условию

Отсутствие сведений не означает запрет. Курьер с неизвестной категорией C - 1,
с прямо указанной категорией B - 0. QA с неизвестной удалёнкой - 1;
обязательный офис при запросе удалёнки - 0. Не угадываем технологии и опыт.
Конкретное требование в описании важнее обобщённого поля. Например, повар
с полем «без опыта», но обязательным годом стажа в тексте - 0 для новичка.
Соседняя технология не подтверждает нужную: frontend на Vue без React - 1.
Помощник/руководитель допустим, если запрос не ограничивает уровень и задачи
действительно подходят. У каждой оценки есть обоснование в reason

Отбор по всему корпусу из 2058 вакансий через build_candidate_pool в evaluation.py:

- top-10 BM25: название повторяется трижды, затем текст; токены в нижнем регистре,
  без стоп-слов и стемминга, остальные параметры bm25s стандартные;
- top-10 TF-IDF по названию: char_wb, n-граммы 3-5, косинусная близость;
- прежние примеры первых шести намерений также сохранены

Размечено объединение, от 11 до 22 кандидатов в исходном пуле на запрос. Колонка selection
содержит метод и позицию в выдаче либо manual; она не вычисляет релевантность.
Запросы и оценки редактируются в data/queries.csv и data/qrels.csv.
make prepare-labels сохраняет Parquet с annotator=codex, guideline_version=2.
Независимой проверки человеком не было

Top-10 обеих систем размечены полностью. Перед вычислением NDCG@10/MRR@10
вызываем require_judged_results: неизвестные пары отклоняются, сначала
дополняется разметка. Выдача не сокращается до известных документов.
Для новой системы нужно оценить новые результаты. NDCG нормируется по
известным оценкам, не по всем релевантным вакансиям корпуса. Recall@100 пока
не используем как полноту корпуса: полный набор релевантных документов
неизвестен. Для MRR релевантны оценки >=1. Метрики вычисляет команда evaluate через ranx

Разбиения различаются намерениями. Положительные группы описаний не пересекаются;
общие нерелевантные кандидаты допустимы, индекс корпуса общий. Разметка
отложенных запросов не используется для обучения или настройки. Test открыт
и просмотрен автором разметки; это не независимая слепая оценка. Четыре тестовых
намерения подходят для первого сравнения, а не для сильных статистических выводов.
В блоках 13-15 добавлено 55 оценок из dense, RRF, weighted_sum и reranker.
Прежние 199 оценок не изменены. Теперь размечено объединение настоящих top-10
сравниваемых вариантов на validation и выбранных BM25/dense/RRF на test.
Валидационная сетка: k=20/60 для RRF, вес dense 0.25/0.5/0.75 для min-max суммы,
по 50/100 кандидатов. Reranker сравнивался с 20/50 кандидатами; тест для него
не использовался, поскольку он отклонён по validation. Новые положительные
группы также не пересекаются между разбиениями. Тестовые документы просмотрены
для разметки по прежней инструкции, параметры по тестовым метрикам не выбирались.
Расширение пула меняет идеальную выдачу NDCG. Старые значения на 199 оценках
нельзя сравнивать с новыми напрямую; все базовые варианты пересчитаны на 254.
Результаты и CPU-ограничения описаны в docs/experiments.md

## Поиск

Версионируем корпус, запросы, разметку qrels и шкалу релевантности 0/1/2.
При расширении набора часть разметки проверяется вторым оценщиком. Близкие дубликаты и перефразировки
группируются до разбиения. Отложенные запросы не используются для обучения
и отбора отрицательных примеров. Неразмеченный документ не считается заведомо
нерелевантным. Размечаем объединённую выдачу разных систем и указываем покрытие

На одинаковых данных сравниваем BM25, поиск по эмбеддингам, гибридный поиск,
готовую модель ранжирования. Дообучение и его сравнение отложены. Главная метрика - NDCG@10.
Recall@100 оценивает отбор относительно известных релевантных документов.
MRR@10 использует заранее выбранный порог релевантности. Показываем категории
запросов и доверительные интервалы парного бутстрэпа; обучение повторяем
с несколькими начальными состояниями генератора случайных чисел

Настраиваем систему на валидационной выборке. Тестовая выборка служит для итогового
отчёта. Полезное улучшение и допустимые отклонения определяем после измерения
базового варианта, без выдуманных значений метрик

## Корректность

Проверяем повторную загрузку, конкурентные обновления версий, прерывание и
возобновление индексации, фильтры, удаление, переключение выпуска, отмену запросов
и переполнение очереди. Используем несколько процессов. Успешные тесты
подтверждают проверенные сценарии, но не исключают все возможные гонки

## Производительность

Фиксируем оборудование, корпус, модели, конфигурацию и число процессов API.
Измеряем p50/p95/p99 полного запроса, заданные и достигнутые RPS, ошибки, таймауты,
отказы, ожидание очереди, использование пула и RAM/VRAM. Разделяем холодный
и прогретый запуск, успешные и отклонённые запросы.
Бюджет задержки и нагрузки определяем после первого измерения на оборудовании.
Проверяем отказ PostgreSQL/Redis, восстановление и поведение при недоступности сервисов

## Воспроизводимость и выпуск

Сохраняем версии данных, предобработки, эмбеддингов, модели ранжирования и индекса,
хеш конфигурации, идентификатор версии кода и отчёт оценки. Подготовка, обучение
и оценка воспроизводятся из чистого окружения. Фиксируем допустимое численное
отклонение, не обещая побитового совпадения обучения на GPU.
Перед выпуском проверяем качество на валидации, совместимость артефактов
и измеренную производительность. Демонстрируем запуск и откат версии

Первый BM25 и TF-IDF по названиям измерены на одинаковой validation. Подробности
и ограничение статистической уверенности записаны в docs/experiments.md. Отчёты размещаются в
`artifacts/reports`, выводы экспериментов - в `docs/experiments.md`


## Первый реализованный поиск

Токенизация BM25-v1 сохраняет C++, C# и .NET и односимвольные слова.
Это отличается от исходного пула bm25s со стандартным шаблоном. Новая выдача
добавила три пары: водитель для перевозки пассажиров вместо доставки товаров,
электрогазосварщик для запроса повара и продажи с обязательным привлечением
клиентов для запроса без поиска. Всем трём присвоен 0 с конкретным обоснованием.
На конец блока 12 было 199 оценок по 166 документам; текущий пул описан выше. Разметка по-прежнему выполнена Codex.
Старые оценки не менялись после измерения метрик

Для настоящей короткой выдачи не добавляются документы с нулевым BM25-score.
require_judged_results проверяет доступные первые десять результатов и не требует
искусственного заполнения до десяти. Метрики пустой выдачи равны нулю.
В NDCG используется линейный gain, IDCG нормируется по известным оценкам;
MRR и Recall используют threshold 1. В ранкере ranx сохраняется исходный порядок,
включая одинаковые оценки BM25. Неразмеченный tail до 100 не влияет на NDCG@10/MRR@10;
Recall@100 измеряет покрытие известных положительных оценок и явно помечен так

compare_reports отклоняет разные версии корпуса, запросов, разметки, split
и определения метрик. Для изменения NDCG используется парный бутстрэп
2000 выборок, seed 42, интервал 95%. Quality gate работает по заданному
допуску среднего изменения NDCG; сам по себе pass не доказывает улучшение.
Численного SLA и универсального порога качества по первым четырём запросам нет

Измеренные задержки относятся к прогретому offline BM25 top-100 без PostgreSQL,
HTTP, Redis и reranker. Это не задержка готового API и не нагрузочный тест
