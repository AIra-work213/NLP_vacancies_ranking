# Правила проекта

Правила действуют для всего репозитория и его подкаталогов.


- Пиши ответы, документацию, docstring и пояснения на русском языке, в комментариях не ставь точки и длинные тире, если увидишь их - удаляй. Имена файлов,
  переменных, функций, классов, ключи API и технические идентификаторы сохраняй
  в принятом для Python и используемых библиотек формате.
- Не создавай коммиты, не добавляй изменения в staging и не меняй историю Git,
  пока пользователь явно не отменит этот запрет.
- Пиши простой, понятный код с содержательными именами и явным потоком выполнения.
- Разделяй смысловые блоки пустыми строками, включая Dockerfile и конфигурации.
  Не уплотняй файл ради меньшего числа строк; сохраняй единый стиль отступов.
- Следуй PEP 8 и PEP 257. Лимит строки для форматирования — 88 символов.
- Описывай классы и функции краткими docstring. При необходимости объясняй
  поведение, владение ресурсами и ограничения. Не добавляй шаблонные описания.
- Не используй отдельные или строчные комментарии через `#` в Python-коде,
  включая TODO, noqa и type-ignore. Объяснения размещай в docstring или документации.
- Поясняющие комментарии в конфигурационных файлах также пиши на русском.
- Не добавляй абстракции, универсальные механизмы и зависимости без конкретной задачи.
- Это учебный пет-проект: сложность должна помогать реализовывать согласованный
  функционал и понимать код. Не создавай отдельные паспорта, реестры хешей
  и отчёты ради формальности. Тестируй важное поведение; не разрабатывай
  вспомогательные механизмы только ради возможности их протестировать.
- Каждая параллельная задача владеет отдельной AsyncSession. Ограничивай
  параллельность ввода-вывода и инференса. Не блокируй цикл событий вычислениями.
- Проверяй каждое изменение через Ruff и проверку форматирования. Запускай mypy
  и необходимые тесты при изменении поведения или типов.
- В MLflow называй эксперимент по модели и цели, например `multilingual-e5-small — подбор гиперпараметров`
  В названии запуска указывай метод поиска и разбиение, параметры сохраняй отдельно
- Не выдавай заготовки за реализованный поиск, обучение, защиту от гонок
  или измеренное качество.

Обязательные проверки стиля:

```bash
uv run ruff check .
uv run ruff format --check .
```

## Согласованный стек

Это целевой стек проекта. Наличие технологии в списке не означает, что её
интеграция уже реализована. Приводи существующий каркас к этим решениям только
в рамках согласованного с пользователем этапа работы.

| Область | Решение |
| --- | --- |
| Язык и зависимости | Python 3.12, uv, pyproject.toml, uv.lock |
| API | FastAPI, Uvicorn |
| Схемы и настройки | Pydantic, pydantic-settings |
| База данных | PostgreSQL с pgvector; SQLAlchemy в асинхронном режиме, asyncpg |
| Миграции | Alembic |
| Лексический поиск | bm25s |
| Эмбеддинги и ранжирование | PyTorch, Transformers, sentence-transformers |
| Кеш поиска | Redis, асинхронный клиент redis-py через redis.asyncio |
| Объектное хранилище | MinIO, официальный Python SDK minio |
| Эксперименты и артефакты моделей | MLflow локально в Docker Compose |
| Версионирование данных и пайплайны | DVC с remote в MinIO |
| Подготовка данных | Pandas, Parquet через PyArrow |
| Конфигурации пайплайнов | YAML с проверкой через Pydantic |
| Метрики качества поиска | ranx |
| Логи | structlog со стандартным logging |
| Мониторинг | Prometheus, Grafana, prometheus-fastapi-instrumentator, prometheus-client |
| Тесты | pytest, pytest-asyncio, HTTPX |
| Нагрузочные проверки | Locust |
| Стиль и типизация | Ruff, mypy |
| Сборка и окружение | Docker, Docker Compose, Makefile |
| CI/CD | Исключено по решению пользователя, проверки запускаются локально |
| Демонстрационный интерфейс | Streamlit, обращающийся к FastAPI через HTTP |

### Границы первой версии

- Поиск по вакансиям на русском языке с сохранением английских названий технологий.
- Первый корпус — выборка 3000 вакансий Mendeley Data, версия 1. Источник
  и особенности данных кратко описаны в README. Поле города отсутствует.
- Подготовленные документы, запросы и оценки релевантности хранятся в Parquet.
- Оценки релевантности: 0 — не подходит, 1 — частично подходит, 2 — подходит.
  Первый набор по просьбе пользователя размечен Codex, без независимой проверки
  человеком. Инструкция и ограничения описаны в docs/evaluation.md.
- Фильтры: город, формат работы и уровень опыта, если эти поля есть в датасете.
  Фильтры применяются при отборе кандидатов для поиска.
- Подготовка данных, построение индекса и оценка запускаются отдельными
  CLI-командами и через DVC; Makefile предоставляет удобные команды запуска.
- Redis используется для кеширования поиска. Ключ учитывает запрос, фильтры,
  число результатов и версию индекса и моделей. Записи имеют TTL.
  При недоступности кеша поиск выполняется без него.
- Очередь задач и отдельный воркер отложены до этапа автоматического обновления
  документов. Брокер и библиотека выполнения задач пока не выбраны.
- Дообучение отложено. Для поиска выбраны готовые E5-small и многоязычная
  MiniLM; режим обучения не выбран.
  Первое рабочее окружение — CPU; устройство выполнения задаётся конфигурацией.
- По validation выбран RRF k=60 по 50 кандидатов BM25/dense.
  Reranker выключен по умолчанию: измеренный результат хуже RRF.
- Qdrant не используется: для векторного поиска выбран pgvector.
- Клиент приложения для MinIO — minio, а не boto3. Транзитивные зависимости
  S3-поддержки DVC не являются выбором SDK приложения.
- Не добавляй Kubernetes, Airflow и Kafka на этом этапе.
- LangChain не утверждён как часть стека. Потребность в разбиении документов,
  конкретный алгоритм и библиотека определяются при реализации после анализа
  длины текстов и ограничений токенизаторов моделей.

### Тестирование, качество и конкурентный доступ

- API-тесты используют HTTPX AsyncClient и настоящие HTTP-запросы к запущенному
  серверу. Не подменяй их TestClient или ASGITransport.
- Интеграционное окружение запускается отдельным Docker Compose с изолированными
  тестовыми данными. Набор сервисов определяется проверяемым сценарием.
- Создавай Redis-клиент с пулом соединений в lifespan отдельно для каждого
  процесса API и закрывай при остановке. Объекты pipeline не разделяются между
  параллельными задачами.
- Синхронный SDK MinIO не вызывается напрямую из асинхронного обработчика:
  блокирующие операции выполняются вне цикла событий с ограничением параллельности.
- Асинхронный ввод-вывод и параллельный инференс рассматриваются отдельно.
  Ограничивай вычислительные задачи с учётом ресурсов компьютера.
- Идемпотентность, транзакции и проверка версии документа должны защищать
  конкурентные обновления. Брокер или блокировка сами по себе не доказывают
  отсутствие гонок данных.
- Основная метрика поиска — NDCG@10; дополнительно оцениваются Recall@100
  для отбора кандидатов и MRR@10 с явно заданным порогом релевантности.
- Разделяй обучающие, валидационные и тестовые данные без утечки дубликатов.
  Настройки подбираются на валидации; тестовая выборка служит итоговой проверкой.
- Сравнивай варианты на одном наборе запросов. Измеряй задержки, пропускную
  способность, ошибки и потребление ресурсов; пороги качества определяются
  после базовых измерений, без выдуманных результатов и SLA.
- Используй контекст запроса для request_id и очищай его в начале обработки.
  Проверяй изоляцию логов параллельных запросов. В контейнерах логи выводятся
  в JSON, при локальной разработке — в читаемом виде.
- При нескольких процессах API явно настраивай сбор метрик Prometheus;
  не считай метрики одного процесса метриками всего сервиса.


## Размер и структура каркаса

- Сохраняй src-layout и согласованное разделение server, ml, pipelines, mlops,
  domain и core внутри nlp_ranker.
- Сервер организован в server/controller, server/service, server/model
  и server/repository. Redis находится в repository/cache, PostgreSQL
  в repository/postgres, MinIO в repository/s3.
- Контроллеры принимают HTTP-параметры и вызывают сервисы. Поиск, кеширование
  и координация чтения документов относятся к сервисам; SQL и внешние SDK
  относятся к репозиториям. ORM-модели и HTTP-схемы хранятся в model.
- ML-инференс, поисковые алгоритмы, оценку и дообучение разделяй в ml.
  Алгоритмы и модели не импортируют сервер, репозитории или ORM.
  Запуск этапов и владение их ресурсами относятся к pipelines.
- Не создавай папки и отдельные файлы под каждую будущую функцию или интеграцию.
- Выделяй подпакет только когда существующий код действительно требует разделения.
- Не добавляй пустые уровни domain/application/infrastructure, utils или обёртки
  над библиотеками без конкретной необходимости.
- Полные документы хранятся в PostgreSQL и получаются по document_id.
  Разбиение текста, объединение фрагментов и вход reranker определяются при разработке.


## Проектирование и паттерны

- Следуй SOLID соразмерно задаче: у компонента одна понятная ответственность,
  контракты небольшие, реализации подменяются без изменения вызывающего кода.
- Разделяй HTTP-схемы, алгоритмы поиска и доступ к хранилищам. Поисковые алгоритмы
  не импортируют FastAPI, Streamlit или ORM-модели.
- Передавай зависимости явно через параметры и FastAPI Depends. Сборка
  зависимостей выполняется в create_app и lifespan; app.state используется
  на границе HTTP, а не как глобальный контейнер для всего кода.
- Используй фабричные функции для сборки, Strategy для заменяемых алгоритмов,
  Repository для доступа к БД и контекстные менеджеры для владения ресурсами,
  когда они решают реальную задачу. Предпочитай композицию наследованию.
- Не реализуй все паттерны заранее. Не добавляй классы-посредники, базовые классы,
  универсальные фабрики или интерфейсы ради формального соответствия паттерну.
- Не скрывай commit и rollback в методах репозитория: границей транзакции владеет
  вызывающий сценарий. Отдельный Unit of Work добавляется только при необходимости
  координации нескольких репозиториев; async with session.begin() достаточно
  для простого сценария.
- Регистрируй освобождение ресурса сразу после его создания. При ошибке
  инициализации уже созданные ресурсы должны закрываться.
- Кеширование и внешние SDK подключай на границе алгоритмов, без зависимости
  математических функций от Redis или MinIO. Обёртка оправдана конкретным
  поведением, а не простым переименованием вызова библиотеки.
- Паттерны не требуют дополнительных уровней каталогов. Сохраняй компактную
  структуру до появления достаточного объёма работающего кода.


## Порядок реализации

- Следуй блокам плана в docs/implementation.md. Реализуй один блок за один этап.
- После завершения блока остановись и покажи изменённые файлы, суть изменений
  и результаты проверок. Следующий блок начинай после нового указания пользователя.
- Если блок не завершён, сообщай конкретный оставшийся шаг и причину;
  не отмечай его готовым по наличию заготовок.
